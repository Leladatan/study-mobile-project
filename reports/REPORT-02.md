### Hook useCatalog

Вся логика каталога лежит в `src/hooks/useCatalog.ts`. Экран только получает из него данные
и функции и рисует интерфейс.

Состояние:

```ts
const [query, setQuery] = useState('');
const [appliedQuery, setAppliedQuery] = useState('');
const [regionId, setRegionId] = useState<RegionId | null>(null);
const [selectedIds, setSelectedIds] = useState<string[]>([]);
```

- `query` — текст в поле поиска;
- `appliedQuery` — текст, по которому фильтруется список;
- `regionId` — выбранный регион или `null`, если выбраны все;
- `selectedIds` — выбранные карточки.

### Задержка поиска

```ts
useEffect(() => {
  const timer = setTimeout(() => setAppliedQuery(query), SEARCH_DELAY);
  return () => clearTimeout(timer);
}, [query]);
```

Когда меняется `query`, эффект ставит таймер на 250 мс. Если пользователь продолжает печатать,
cleanup отменяет старый таймер, и список обновляется один раз — после паузы. Эффект зависит
от `query`, а меняет `appliedQuery`, поэтому бесконечного цикла нет.

### Поиск и фильтр

```ts
const visibleTopics = useMemo<Topic[]>(() => {
  const needle = appliedQuery.trim().toLowerCase();
  return TOPICS.filter((topic) => {
    if (regionId !== null && topic.regionId !== regionId) return false;
    if (needle.length === 0) return true;
    return (
      topic.title.toLowerCase().includes(needle) ||
      topic.capital.toLowerCase().includes(needle)
    );
  });
}, [appliedQuery, regionId]);
```

Запрос и названия переводятся в нижний регистр, поэтому `JAPAN` и `japan` работают одинаково.
Пустой запрос возвращает все страны. Отфильтрованный список не хранится в state, а каждый раз
считается из запроса и региона — так он не может разойтись с тем, что выбрал пользователь.

### Выбор карточек

```ts
const toggleSelection = useCallback((topic: Topic) => {
  setSelectedIds((previous) =>
    previous.includes(topic.id)
      ? previous.filter((id) => id !== topic.id)
      : [...previous, topic.id],
  );
}, []);
```

Массив не меняется напрямую. При добавлении создаётся новый массив через `[...previous, id]`,
при удалении — через `filter`. Перед добавлением проверяется `includes`, поэтому дубликатов нет.
Счётчик «Выбрано» — это длина массива.

### Поле поиска

Основные props поля в `SearchField.tsx`:

```tsx
<TextInput
  style={styles.input}
  value={value}
  onChangeText={onChange}
  placeholder={placeholder ?? 'Страна или столица'}
/>
```

Поле управляемое: текст берётся из state, а при вводе state обновляется через `onChangeText`.
Поэтому кнопка «Сбросить фильтры» может очистить поле из кода.

### Фильтр по региону

В ленте есть чип «Все регионы». Повторное нажатие на выбранный регион снимает фильтр:

```tsx
onPress={() => onSelect(selected === region.id ? null : region.id)}
```

### Список

```tsx
const renderItem = useCallback<ListRenderItem<Topic>>(
  ({ item, index }) => (
    <TopicCard
      topic={item}
      onPress={toggleSelection}
      featured={index === 0 && !filtersActive}
      selected={isSelected(item)}
    />
  ),
  [toggleSelection, isSelected, filtersActive],
);

const keyExtractor = useCallback((item: Topic) => item.id, []);
```

`FlatList` рисует только те карточки, которые видны на экране. Ключ строки — `item.id`, а не
индекс: после фильтрации индексы меняются, а `id` остаётся тем же. Первая карточка выделяется
только тогда, когда фильтры не активны, иначе выделение прыгало бы при каждом поиске.

Если ничего не найдено, `FlatList` показывает `ListEmptyComponent` — текст с причиной и кнопку
«Сбросить фильтры».

Выбор после перехода на `Set`:

```ts
const toggleSelection = useCallback((id: string) => {
  setSelectedIds((previous) => {
    const next = new Set(previous);
    if (next.has(id)) {
      next.delete(id);
    } else {
      next.add(id);
    }
    return next;
  });
}, []);
```

`add` и `delete` вызываются у копии `next`, а старый `previous` не меняется, поэтому state
по-прежнему не мутируется. Проверка «выбрана ли карточка» теперь `selectedIds.has(id)` — она
не перебирает весь список, как `includes`.

### Проблемы и решения

**1. Список обновлялся бы на каждую букву.** Если фильтровать по тексту в поле напрямую, при

## 05 / КОНТРОЛЬНЫЕ ВОПРОСЫ

### Контрольный вопрос 1

**Чем state отличается от обычной локальной переменной компонента?**

Обычная переменная создаётся заново при каждой перерисовке и не обновляет экран, когда меняется.
State React хранит между перерисовками, а вызов функции-сеттера перерисовывает компонент.
Если бы запрос хранился в `let query = ''`, текст в поле пропадал бы после каждой перерисовки.

### Контрольный вопрос 2

**Почему TextInput называется управляемым компонентом?**

Потому что его значение задаёт React state, а не само поле. `SearchField` получает `value`
из `query`, а при вводе вызывает `onChangeText`, который обновляет state. Благодаря этому
поле можно очистить из кода, например кнопкой «Сбросить фильтры».

### Контрольный вопрос 3

**Зачем FlatList нужен стабильный keyExtractor?**

По ключу React понимает, какая строка какая между перерисовками. Если ключ — индекс, после
фильтрации одна страна получит ключ другой, и React перепутает строки. Код страны `item.id`
не меняется, поэтому каждая карточка остаётся на своём месте.

### Контрольный вопрос 4

**Почему props и state рассматриваются как неизменяемые снимки?**

React решает, нужно ли перерисовать экран, сравнивая ссылки на старое и новое значение. Если
изменить массив через `push`, ссылка останется той же, и React может не заметить изменение.
Поэтому создаётся новый массив через `[...previous, id]` или новый `Set` через `new Set(previous)`.

### Контрольный вопрос 5

**Какие два ограничения определяют допустимое место вызова hooks?**

Первое: hooks вызываются только на верхнем уровне — не в условиях, циклах, вложенных функциях
и не после `return`. Второе: только в компонентах или в других hooks. React отличает один
`useState` от другого по порядку вызовов, и если порядок изменится, значения перепутаются.

### Контрольный вопрос 6

**Когда нужен useEffect и зачем ему cleanup?**

`useEffect` нужен, чтобы работать с тем, что находится вне React: таймерами, подписками,
запросами. В каталоге он ставит таймер для задержки поиска. Cleanup отменяет старый таймер
перед новым запуском и при закрытии экрана, иначе при быстром вводе остались бы лишние таймеры.

### Контрольный вопрос 7

**Как пользовательский hook отделяет логику от отображения?**

В `useCatalog` лежат state, эффект, поиск, фильтр и выбор. Наружу он отдаёт готовые данные
и функции. `CatalogScreen` не знает, как работает фильтрация, и только рисует интерфейс. Когда
данные начнут приходить из API, поменяется hook, а экран останется прежним.

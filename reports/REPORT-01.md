### Тип Topic

Сущность описана в `src/types/topic.ts`:

```ts
export type Topic = {
  id: string;
  title: string;
  description: string;
  imageUrl?: string;
  capital: string;
  regionId: RegionId;
  regionName: string;
  incomeLevel: IncomeLevel;
  population: number;
  populationYear: string;
  iso2: string;
};
```

`id`, `title` и `description` обязательные. `imageUrl` необязательный — это обозначает знак `?`.
Остальные поля — данные о стране. `RegionId` и `IncomeLevel` — не просто строки, а списки
допустимых значений, например `'EAS' | 'ECS' | ...`. Если в данных ошибиться в коде региона,
TypeScript сразу покажет ошибку.

### Данные

Страны лежат в `src/data/topics.ts` в массиве `TOPICS: Topic[]`. Благодаря типу массива каждый
объект проверяется на соответствие `Topic`. Вот пример — Канада:

```ts
{
  id: 'CAN',
  title: 'Canada',
  description:
    'Вторая страна мира по площади. Большая часть населения живёт вблизи границы с США.',
  capital: 'Ottawa',
  regionId: 'NAC',
  regionName: REGION_NAMES.NAC,
  incomeLevel: 'High income',
  population: 41651653,
  populationYear: '2025',
  iso2: 'CA',
},
```

`id` — код страны из трёх букв. Он уникальный и не меняется. У Канады специально нет `imageUrl`:
на ней видно, как карточка выглядит без картинки.

### Компонент TopicCard

Контракт карточки:

```tsx
export type TopicCardProps = {
  topic: Topic;
  onPress: (topic: Topic) => void;
  featured?: boolean;
};
```

- `topic` — данные страны;
- `onPress` — функция, которую карточка вызывает при нажатии;
- `featured` — необязательный prop, делает карточку крупнее. По умолчанию `false`.

`children` не используется: внутрь карточки ничего не вкладывается.

Если у страны есть флаг, показывается картинка, если нет — блок с кодом страны:

```tsx
{topic.imageUrl ? (
  <Image
    source={{ uri: topic.imageUrl }}
    style={[styles.flag, featured && styles.flagFeatured]}
    resizeMode="cover"
    accessibilityIgnoresInvertColors
  />
) : (
  <View style={[styles.flag, styles.placeholder, featured && styles.flagFeatured]}>
    <Text style={styles.placeholderText}>{topic.id}</Text>
  </View>
)}
```

Карточка не импортирует данные стран. Она получает объект через props и при нажатии вызывает
`onPress(topic)`, а что делать дальше, решает экран.

### Экран каталога

Экран хранит выбранную страну в state:

```tsx
const [selected, setSelected] = useState<Topic | null>(null);

const handlePress = (topic: Topic) => {
  setSelected(topic);
};
```

И выводит карточки перебором массива:

```tsx
{TOPICS.map((topic, index) => (
  <TopicCard
    key={topic.id}
    topic={topic}
    onPress={handlePress}
    featured={index === 0}
  />
))}
```

Разметка карточки написана один раз, экран только передаёт в неё данные. Первая карточка
выделена через `featured`. При нажатии `handlePress` сохраняет страну, и над списком появляется
её название и столица. Список лежит в `ScrollView`, потому что `FlatList` по методичке вводится
в Sprint 2.

Путь нажатия: `Pressable` → `onPress(topic)` → `handlePress` → `setSelected` → экран
перерисовывается.

### Metro, Hermes и Fast Refresh

- **Metro** собирает код проекта и отдаёт его на телефон или в браузер.
- **Hermes** выполняет этот код на устройстве. В `app.json` движок не указан, поэтому
  используется Hermes по умолчанию. Это видно в адресе бандла (`transform.engine=hermes`),
  а сборка под Android даёт файл `.hbc` — байт-код Hermes.
- **Fast Refresh** проверен: после изменения `title` в `src/data/topics.ts` экран обновился
  без перезапуска.

### Проблемы и решения

**1. Backlog не совпал с методичкой.** В backlog первым спринтом стояла загрузка списка из API,
а методичка запрещает API в первых двух спринтах. Загрузка перенесена на Sprint 3, для текущих
задач добавлены истории US-10 и US-11.

**2. FlatList нельзя до Sprint 2.** 12 карточек не помещаются на экран, поэтому список
завёрнут в `ScrollView`.

**3. Флаги появляются не сразу.** Картинки грузятся из интернета, и сначала на их месте было
пусто. У `Image` задан цвет фона, теперь место под флагом видно сразу.

**4. Тег поставлен раньше времени.** Тег `sprint-1` был создан до слияния pull request
и указывал на коммит Sprint 0. Тег удалён и поставлен заново после слияния.

**5. OneDrive мешает git.** При переключении веток git не смог удалить папку `src/components`,
потому что её держал OneDrive. Помогает пауза синхронизации.

### Ретроспектива

- **Получилось:** карточку можно переиспользовать без изменений.
- **Мешало:** расхождение backlog с методичкой и ошибки при публикации.
- **Долг:** данные лежат в коде; `ScrollView` рисует все карточки сразу.
- **Дальше:** `FlatList`, поиск, фильтр и выбор карточек.

## 05 / КОНТРОЛЬНЫЕ ВОПРОСЫ

### Контрольный вопрос 1

**Чем компонент отличается от экрана приложения?**

Компонент — отдельная часть интерфейса, которую можно использовать много раз. `TopicCard` рисует
одну страну и ничего не знает об остальном приложении. Экран — то, что пользователь видит целиком.
`CatalogScreen` хранит состояние и собирает интерфейс из компонентов.

### Контрольный вопрос 2

**Зачем данные передаются в TopicCard через props?**

Чтобы карточка не зависела от конкретных данных. Один компонент рисует все 12 стран, получая
каждый раз другой объект. Если данные начнут приходить из API, карточку менять не придётся.

### Контрольный вопрос 3

**Почему fixtures не должны находиться внутри карточки?**

Тогда карточка сможет показывать только эти данные и её нельзя будет переиспользовать. Хранение
данных и их отображение — разные задачи, поэтому данные лежат в `src/data/topics.ts`.

### Контрольный вопрос 4

**Чем обязательный prop отличается от optional prop?**

Обязательный prop нужно передавать всегда, иначе TypeScript покажет ошибку. У `TopicCard`
обязательны `topic` и `onPress`. Необязательный prop помечается `?` и может отсутствовать,
поэтому у `featured` есть значение по умолчанию `false`.

### Контрольный вопрос 5

**Что TypeScript проверяет до запуска приложения, а что он не проверяет?**

До запуска TypeScript проверяет типы: переданы ли нужные props, правильные ли поля в данных,
подходит ли функция под тип callback. Он не проверяет то, что происходит во время работы:
загрузилась ли картинка, какие данные пришли из сети, правильно ли работает логика. Metro при
сборке просто удаляет типы, поэтому проверять их нужно отдельно командой `npm run typecheck`.

### Контрольный вопрос 6

**Какую задачу выполняет Metro?**

Metro — сборщик. Он собирает файлы проекта в один бандл, отдаёт его на устройство и пересобирает
при изменениях. На этом работает Fast Refresh.

### Контрольный вопрос 7

**Какую задачу выполняет Hermes?**

Hermes — движок JavaScript на устройстве. Он выполняет бандл, который заранее переведён в байт-код,
поэтому приложение быстрее запускается и тратит меньше памяти.

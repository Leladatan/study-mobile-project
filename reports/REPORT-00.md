## 02 / ВЫПОЛНЕНИЕ

### Выполнение работы

#### Реализованные изменения

В рамках Sprint 0 создан проект **WorldDex** — мобильный справочник стран мира. Поскольку спринт
нулевой, инкремент состоит не из пользовательской функциональности, а из проекта, документации
и проверенного источника данных.

| Артефакт | Содержание |

| `README.md` | Название, описание, тематика, аудитория, основной сценарий, состояние среды |
| `docs/product-concept.md` | Проблема, идея, аудитория, сценарий, границы MVP, кандидат API, риски |
| `docs/backlog.md` | Product backlog из 9 пользовательских историй, 6 критериев приёмки для US-1 |

| `assets/data/countries.fallback.json` | Резервный источник данных: 12 стран из реальных ответов API |

Сформулированная концепция: **один экран поиска → одна карточка страны → все базовые факты,
сопоставимые между странами и доступные offline.** Целевая аудитория — студенты 1–2 курса и
старшеклассники, готовящие доклады по географии и экономике.

#### Ключевые технические решения

**1. Expo вместо React Native CLI.** Expo даёт запуск на физическом устройстве через Expo Go без
установки Android Studio и JDK, что сокращает время до первой рабочей сборки. Шаблон
`blank-typescript` выбран сознательно: он не тянет навигацию и глобальное состояние, то есть
не нарушает ограничение спринта «не добавлять Redux, базу данных, навигацию и сложную архитектуру».

**2. World Bank Indicators API v2 как источник данных.** Ключевое решение спринта. Первоначальный
кандидат — REST Countries v3.1 — оказался нерабочим (см. раздел «Возникшие проблемы»). Итоговый
выбор обоснован тремя свойствами: доступ без API-ключа и регистрации (значит, ограничение «не
размещать секреты в репозитории» выполняется автоматически), официальный источник с лицензией
CC BY-4.0 и единый набор полей для всех стран за один период — это и есть техническая основа
заявленной сопоставимости данных.

**3. Разделение источников: данные и изображения.** World Bank API не отдаёт флаги, поэтому
изображения берутся с `flagcdn.com` по коду `iso2Code`, который приходит вместе с данными страны.
Это позволяет не тащить в проект тяжёлый набор изображений и не искать API, покрывающий всё сразу.

**4. Резервный источник, сгенерированный из реальных ответов API.** Файл
`countries.fallback.json` не написан вручную, а собран из фактических ответов
`/v2/country` и `/v2/country/{ISO3}/indicator/SP.POP.TOTL`. В секции `meta` сохранены исходные
URL, идентификатор индикатора, дата генерации и лицензия. Это исключает расхождение форматов
между основным и резервным источником в Sprint 2 при реализации US-5.

**5. Экран-заглушка вместо интерфейса.** `App.tsx` показывает название продукта, источник данных
и следующий шаг. Задача экрана — подтвердить сборку и запуск, а не изобразить будущий справочник:
ограничение «не создавать полноценный пользовательский интерфейс в рамках Sprint 0» соблюдено.

**6. Усиление `.gitignore`.** Шаблон Expo игнорирует только `.env*.local`. Добавлены `.env`
и `.env.*` с исключением `.env.example`, чтобы ограничение о секретах выполнялось и в случае,
если в следующих спринтах появится источник данных с ключом.

### Возникшие проблемы и решения

**Проблема 1. Выбранный API оказался задепрекейчен.**

В качестве кандидата изначально рассматривался REST Countries v3.1 — самый распространённый
в учебных проектах открытый справочник стран. Диагностика: вместо чтения документации был
выполнен реальный запрос.

```
GET https://restcountries.com/v3.1/name/japan
HTTP 200
{ "success": false, "data": null,
  "errors": [{ "message": "This API version has been deprecated...
     migrate to our new version (v5)." }] }
```

Ответ приходит с кодом **200**, а не 404 или 410, поэтому проблема не обнаружилась бы при
поверхностной проверке «сервис отвечает». Дальнейшая проверка показала, что v5 переехала на
`https://api.restcountries.com/countries/v5/` и требует регистрации и заголовка
`Authorization: Bearer <ключ>`, а демо-ключ `rc_live_demo` возвращает один фиксированный пример
вместо реальных данных.

**Решение:** кандидат заменён на World Bank Indicators API v2 — без ключа и регистрации,
с официальной документацией. Замена сделана до написания кода, поэтому обошлась в переработку
одного раздела документации, а не в переделку слоя данных в Sprint 2.

**Проблема 2. API отдаёт агрегаты вместе со странами.**

Запрос `/v2/country?format=json&per_page=300` возвращает 295 записей, но среди них 78 — это
не страны, а агрегаты («Africa Eastern and Southern», «High income», «Euro area»). Без фильтрации
пользователь увидел бы в справочнике несуществующие страны.

**Решение:** агрегаты отличаются значением `region.id === "NA"`. Условие фильтрации проверено
на полном ответе (295 − 78 = **217** реальных стран и территорий) и зафиксировано как критерий
приёмки US-1, а не как комментарий в коде.

**Проблема 3. Ошибки приходят с HTTP-статусом 200.**

Запрос несуществующего кода страны `/v2/country/ZZZ?format=json` возвращает `200 OK` с телом
`[{"message":[{"id":"120","key":"Invalid value",...}]}]`. Стандартная проверка `response.ok`
такую ошибку не поймает, и приложение попыталось бы отрисовать список из объекта с ошибкой.

**Решение:** ограничение задокументировано в концепции, а требование проверять **форму тела
ответа**, а не только HTTP-статус, вынесено в критерий приёмки US-1 № 6 — до начала разработки.

**Проблема 4. Отсутствие флагов и русских названий.**

World Bank API не отдаёт ни изображений флагов, ни локализованных названий стран.

**Решение:** флаги подключаются отдельным источником `flagcdn.com` по коду `iso2Code`
(проверено на четырёх странах, PNG корректны). Русские названия требуют собственного словаря
соответствий — это честно вынесено в backlog отдельной историей US-8 с приоритетом `Could`,
а не замолчано.

### Ретроспектива

**Что получилось.** Ключевое решение спринта — проверять API запросами, а не доверять
документации и популярности. Это стоило нескольких минут и спасло от выбора нерабочего источника,
который проявил бы себя только в Sprint 2, когда цена замены — переписанный слой данных.
Второе — генерация резервного датасета из реальных ответов API: форматы основного и резервного
источника гарантированно совпадут.

**Что мешало.** Соблазн взять привычный REST Countries «как у всех» и не проверять его. Ровно
этот соблазн и был источником главного риска спринта.

**Технический долг.** Долг Sprint 0 минимален, поскольку кода почти нет. Осознанно оставлено:
резервный датасет покрывает 12 стран из 217 и требует расширения к моменту реализации US-5;
запуск на физическом устройстве не автоматизирован и подтверждается скриншотом вручную.

**Возвращено в backlog.** US-8 «Поиск по русскому названию» и US-9 «Избранные страны» вынесены
за границы MVP с приоритетом `Could`. Отказ от карты, графиков динамики и сравнения стран
зафиксирован в разделе «Границы MVP» с обоснованием по каждому пункту.

**Что изменить в Sprint 1.** Начинать со слоя доступа к данным, изолированного от интерфейса:
опыт с REST Countries показал, что источник может смениться, и цена этой смены должна оставаться
низкой.

пользовательский сценарий, backlog из 9 пользовательских историй и экспериментально проверенный
кандидат открытого API с задокументированными ограничениями и резервным источником данных.

**Соответствие цели и критериям приёмки.** Цель — подготовить основу для последующих практических
заданий — достигнута. Семь из восьми критериев приёмки закрыты полностью; восьмой закрыт в части
готовности среды (`tsc --noEmit` без ошибок, `expo-doctor` 21/21), а публикация репозитория
и выдача доступа преподавателю выполняются по готовой инструкции `docs/git-workflow.md`.
Ограничения спринта соблюдены: сетевых запросов, навигации, глобального состояния, базы данных
и полноценного интерфейса в проекте нет, секреты в репозиторий не попадают.

**Закреплённые навыки и инженерные подходы.** Формулирование продуктовой гипотезы через проблему
пользователя, а не через набор функций. Явное проведение границы MVP с письменным обоснованием
каждого отказа. Декомпозиция продукта на пользовательские истории с проверяемыми, а не
декларативными критериями приёмки. И главное — практика проверки внешних зависимостей
экспериментом до принятия решения: именно она выявила, что общепринятый в учебных проектах
источник данных больше не работает.

## 05 / КОНТРОЛЬНЫЕ ВОПРОСЫ

### Контрольный вопрос 1

**Какую проблему решает выбранное приложение?**

**ОТВЕТ.** Базовые факты о стране разбросаны по разным источникам: столица — в одной статье,
население — в другой, классификация по уровню дохода — в третьей. На телефоне это 3–5 переходов
с постоянным зумом. Хуже того, разные статьи ссылаются на разные годы и методики подсчёта,
поэтому две страны нельзя корректно сравнить. И ни один из этих источников не работает без сети —
то есть недоступен ровно в аудитории или в дороге, где справка и нужна.

WorldDex решает все три проблемы одним приёмом: одна карточка на страну, все поля из **одного
официального источника** (World Bank Open Data) за один период, с кэшем и резервным набором
данных для работы offline.

### Контрольный вопрос 2

**Кто является его основным пользователем?**

**ОТВЕТ.** Студенты 1–2 курса и старшеклассники, готовящие доклады, семинары и практические
работы по географии, экономике и обществознанию. Три существенные для продукта характеристики:
работают преимущественно с телефона и часто в дороге; им нужен факт «здесь и сейчас», а не
глубокая аналитика; им важна ссылка на источник, потому что работу проверяет преподаватель —
отсюда требование указывать год наблюдения и происхождение данных.

Дополнительный сегмент — участники квизов и олимпиад по географии: сценарий тот же, но выше
требование к скорости отклика. Продукт сознательно **не** рассчитан на аналитиков, которым нужны
временные ряды и выгрузка в CSV: для них существует World Bank DataBank, и конкурировать с ним
WorldDex не будет.

### Контрольный вопрос 3

**Какой пользовательский сценарий будет реализован первым?**

**ОТВЕТ.** Первой реализуется история **US-1 «Список стран»** — при открытии приложения
пользователь сразу видит список всех стран. Она выбрана первой, потому что это фундамент
основного сценария: без списка невозможны ни поиск (US-2), ни карточка страны (US-3). Кроме того,
US-1 — первая вертикальная связка «сеть → данные → экран», на которой отрабатывается слой доступа
к данным целиком.

Для истории определено 6 проверяемых критериев приёмки: конкретный URL запроса; фильтрация
агрегатов до 217 стран; содержимое строки с обработкой пустой столицы; сортировка по названию;
видимое состояние загрузки; состояние ошибки с кнопкой «Повторить».

### Контрольный вопрос 4

**Какие функции входят в MVP?**

**ОТВЕТ.** В MVP входят пять функций: список всех стран из World Bank API; поиск по названию
(подстрока, регистронезависимый); карточка страны со столицей, регионом, уровнем дохода
и координатами; флаг страны; работа без сети через кэш и резервный источник. К ним примыкают
две истории приоритета `Should` — фильтр по региону и численность населения с годом наблюдения.

Суммарно US-1 … US-7 оценены в 26 story points и распланированы на три спринта. Критерий
включения функции в MVP один: без неё ломается основной пользовательский сценарий «найти факт
о стране менее чем за 30 секунд».

### Контрольный вопрос 5

**От каких функций можно отказаться в первой версии?**

**ОТВЕТ.** Отказ зафиксирован письменно, по каждому пункту — с обоснованием:

- **Авторизация и профиль** — справочник читает открытые данные, персонализировать нечего.
- **Карта и геовизуализация** — дорогая интеграция, не входит в сценарий «найти факт».
- **Графики динамики показателей по годам** — уводят продукт в аналитику, то есть в сегмент,
  который мы сознательно не обслуживаем.
- **Сравнение двух стран рядом** — функция полезная, но основной сценарий без неё работает;
  кандидат на Sprint 4+.
- **Полная локализация и поиск по русским названиям** — вынесены в US-8, требуют собственного
  словаря соответствий ISO-3 → русское название.
- **Push-уведомления и избранное с синхронизацией** — не влияют на ценность MVP.

### Контрольный вопрос 6

**Почему выбранный API подходит для справочника и какой источник станет резервным?**

**ОТВЕТ.** World Bank Indicators API v2 подходит по четырём причинам. Первое — доступ по обычному
HTTP GET **без API-ключа и регистрации**, поэтому ограничение «не размещать секреты в репозитории»
выполняется автоматически, а работа воспроизводится на любой машине. Второе — официальный
источник с лицензией CC BY-4.0 и датой последнего обновления в ответе (`lastupdated: 2026-07-13`),
что важно для аудитории, ссылающейся на данные в учебных работах. Третье — все страны описаны
одинаковым набором полей за один период, а это техническая основа заявленной сопоставимости.
Четвёртое — данные покрывают все поля карточки из основного сценария; проверено шестью реальными
запросами, все вернули 200.

Отдельно стоит сказать, почему **не** был выбран REST Countries — самый очевидный кандидат для
такого справочника. Версия v3.1 задепрекейчена и возвращает ошибку вместо данных, причём с кодом
200; версия v5 требует регистрации и заголовка `Authorization: Bearer`, а её демо-ключ отдаёт
один фиксированный пример. Это выяснилось только при реальном запросе.

**Резервным источником** служит файл `assets/data/countries.fallback.json` — 12 стран с полным
набором полей карточки, сгенерированные из реальных ответов API (в секции `meta` сохранены
исходные URL, индикатор населения, дата генерации и лицензия). Он используется в двух случаях:
устройство offline или API не ответил. При работе на резервных данных интерфейс обязан явно
сообщать об этом пользователю — это критерий приёмки US-5.

### Контрольный вопрос 7

**Как Sprint 1 приблизит продукт к работающей версии?**

**ОТВЕТ.** Sprint 1 закрывает US-1 «Список стран» и US-2 «Поиск страны по названию» — 8 story
points. По итогам спринта появляется первый вертикальный пользовательский инкремент: приложение
обращается к реальному API, фильтрует агрегаты, отображает 217 стран и позволяет найти нужную
по части названия. Это уже шаги 1–2 основного сценария, то есть продукт становится минимально
полезным ещё до появления карточки страны.

Технически Sprint 1 создаёт слой доступа к данным, изолированный от интерфейса, и обработку
состояний загрузки и ошибки. На эту основу в Sprint 2 без переделок ложатся карточка страны,
флаги и работа без сети.

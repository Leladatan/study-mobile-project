# Ретроспектива

## Sprint 0

- **Сделано:** концепция, backlog, выбран и проверен API, создан проект.
- **Мешало:** первый выбранный API, REST Countries, оказался устаревшим — пришлось искать другой.
- **Долг:** названия стран только на английском.
- **Дальше:** первый экран на компонентах.

## Sprint 1

- **Сделано:** тип `Topic`, данные стран в отдельном файле, компонент `TopicCard`, экран каталога.
- **Мешало:** backlog не совпал с методичкой, загрузку из API пришлось перенести на Sprint 3.
  Тег `sprint-1` сначала был поставлен до слияния pull request.
- **Долг:** данные лежат в коде; `ScrollView` рисует все карточки сразу.
- **Дальше:** `FlatList`, поиск, фильтр и выбор.

## Sprint 2

- **Сделано:** `FlatList`, поиск с задержкой, фильтр по региону, выбор карточек, hook `useCatalog`.
- **Мешало:** задержку поиска нужно было сделать без лишних таймеров и бесконечного цикла.
  Тег `sprint-2` снова был поставлен раньше `git pull`.
- **Долг:** выбор не сохраняется после перезапуска приложения.
- **Дальше:** загрузка данных из World Bank API.

## После Sprint 2

- Подключён ESLint, в README дописан раздел «Как проверить».
- Регион и уровень дохода переведены на `enum`, выбранные карточки хранятся в `Set`,

## Sprint 4

Спринт 4 выполнялся раньше спринта 3: номер обозначает тему, а не очередь.

- **Сделано:** цепочка `приложение → apiManager → transportService → сеть`, проверка ответа
  во время выполнения, состояния загрузки и ошибок, порции, отмена и защита от гонок,
  логи с `requestId`, демо-режим, экран карточки, тесты разбора ответа.
- **Мешало:** у World Bank API нет серверного поиска по названию, а на неизвестный код страны
  он отвечает 200 с телом ошибки вместо 404. Пришлось определять «запись не найдена» по форме
  ответа и честно описать границы поиска в интерфейсе и README.
  Отдельно всплыло правило ESLint `react-hooks/set-state-in-effect`: пришлось перенести сброс
  состояния из эффектов в обработчики событий.
- **Долг:** переход в карточку сделан переключением состояния в `App.tsx`, без роутера.
  Поиск не доходит до сервера, потому что API этого не умеет.
- **Дальше:** навигация на Expo Router, прямые ссылки на карточку, `+not-found`.

## Sprint 3

- **Сделано:** корневой `Stack` и группа вкладок, карточка по адресу `/topic/{id}`, экран
  неизвестного адреса, типизированные маршруты, проверка параметра во время выполнения,
  сохранение условий каталога при возврате, прямые ссылки.
- **Мешало:** на вебе при первом переходе Expo Router пересоздаёт дерево маршрутов. Provider
  над навигатором этого не пережил, и возврат сбрасывал поиск. Помогло хранение состояния
  каталога в объекте на уровне модуля.
  Ещё панель вкладок перекрывала низ списка — кнопка «Показать ещё» была недоступна.
- **Долг:** состояние каталога не сохраняется между запусками приложения, на диск ничего
  не пишется. Поиск по-прежнему идёт по загруженным записям.
- **Дальше:** хранилище на устройстве, чтобы справочник открывался без сети.

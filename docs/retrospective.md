# Ретроспектива

Документ ведётся по спринтам. Для каждого фиксируются результат, что мешало, какой технический
долг возник и что делать дальше.

## Sprint 0 — концепция продукта и подготовка проекта

**Результат.** Зафиксированы тематика, аудитория, основной сценарий и границы MVP. Собран
product backlog. Проверен и задокументирован кандидат открытого API. Подготовлена среда:
проверка типов и конфигурации проходят без ошибок.

**Что мешало.** Первоначальный кандидат REST Countries v3.1 оказался задепрекейченным и вместо
данных возвращал ошибку, причём с кодом HTTP 200. Пришлось искать замену и проверять каждый
эндпоинт вручную. Выбран World Bank Indicators API v2 — без ключа и регистрации.

**Технический долг.** Названия стран доступны только на английском: World Bank не отдаёт
локализованные названия. Поиск по русскому названию потребует собственного словаря соответствий.

**Следующий шаг.** Первый экран справочника из переиспользуемых типизированных компонентов.

## Sprint 1 — статическая витрина справочника

**Результат.** Описан тип `Topic`, данные вынесены в отдельный файл fixtures, собран
переиспользуемый компонент `TopicCard` с типизированным контрактом props и callback.
Экран каталога построен на базовых компонентах, разметка карточки не дублируется.

**Что мешало.** Backlog из Sprint 0 распределял истории по спринтам без учёта того, что
сетевые запросы подключаются только начиная со Sprint 3. Историю «Список стран» пришлось
перенести, а под фактическое содержание спринта завести отдельную историю US-10.

**Технический долг.** Данные лежат в коде проекта, а не приходят из источника: при переходе
на API структуру fixtures придётся согласовать с ответом World Bank. Один объект намеренно
оставлен без `imageUrl`, чтобы ветка с заглушкой была рабочей, а не гипотетической.

**Следующий шаг.** Интерактивность: поиск, фильтр, выбор карточек.

## Sprint 2 — интерактивный локальный каталог

**Результат.** Ручной перебор заменён на `FlatList` с типизированным `renderItem` и
`keyExtractor` по стабильному `id`. Добавлены управляемый поиск без учёта регистра, фильтр
по региону со сбросом, выбор карточек со счётчиком и пустое состояние с объяснением.
Состояние и логика вынесены в пользовательский hook `useCatalog`, экран отвечает только
за отображение.

**Что мешало.** Прямолинейная фильтрация по каждому нажатию клавиши перерисовывала список
на каждый символ. Решено разделением состояния: `query` меняется мгновенно и питает поле ввода,
`appliedQuery` обновляется с задержкой 250 мс через `useEffect` с cleanup. Ошибка, которой
удалось избежать: эффект не должен зависеть от значения, которое сам меняет, иначе получается
бесконечный цикл.

**Технический долг.** Выбранные карточки живут только в памяти и теряются при перезапуске
приложения — сохранение появится вместе со слоем хранения. Поиск идёт по названию и столице;
регистр учитывается через `toLowerCase`, что не покроет языки со сложным приведением регистра,
но для латиницы достаточно.

**Следующий шаг.** Подключение World Bank Indicators API: загрузка списка стран по сети,
состояния загрузки и ошибки, переход с локальных fixtures на реальные данные.

# Навигация

Экраны разведены по маршрутам Expo Router. Адрес определяется структурой папки `app/`:
имя файла становится частью адреса.

## Карта экранов

| Файл | Адрес | Что показывает | Как уйти |
| --- | --- | --- | --- |
| `app/(tabs)/index.tsx` | `/` | каталог стран | вкладка или переход в карточку |
| `app/(tabs)/about.tsx` | `/about` | об источнике данных и правилах поиска | вкладка |
| `app/topic/[id].tsx` | `/topic/JPN` | карточка страны | назад или «В каталог» |
| `app/+not-found.tsx` | любой неизвестный адрес | «Такой страницы нет» | «В каталог» |

Служебные файлы адресов не создают:

| Файл | Роль |
| --- | --- |
| `app/_layout.tsx` | корневой `Stack`, общий фон и заголовки |
| `app/(tabs)/_layout.tsx` | навигатор вкладок |

Папка `(tabs)` в скобках — это группа. Она нужна, чтобы объединить экраны под одним навигатором,
и в адрес не попадает: каталог лежит в `app/(tabs)/index.tsx`, но открывается по `/`.

Квадратные скобки в `[id].tsx` означают динамический сегмент. Файл один, а адресов столько,
сколько стран: `/topic/JPN`, `/topic/RUS`, `/topic/BRA`.

## Что лежит в папке маршрутов

В `app/` только маршруты и layout. Модели, хуки и работа с сетью остались в `src/`.
Файлы маршрутов тонкие: они читают параметры, вызывают навигацию и передают готовые props
в экраны из `src/screens/`.

```tsx
// app/(tabs)/index.tsx
const open = useCallback(
  (id: Topic['id']) => router.push({ pathname: '/topic/[id]', params: { id } }),
  [router],
);

return <CatalogScreen onOpen={open} />;
```

## Через адрес передаётся только id

В `params` уходит строка `id`, и ничего больше. Ни объект `Topic`, ни функция, ни ответ сервера.

Причины простые. Ссылка с целой записью была бы огромной и нечитаемой. Данные в ней устарели бы
в момент копирования. А главное — такой адрес нельзя набрать руками или прислать в сообщении,
хотя именно это и есть смысл прямой ссылки.

Карточка получает только код страны и грузит остальное сама через `useTopic`.

## Типы маршрутов

В `app.json` включено `experiments.typedRoutes`. Metro генерирует `.expo/types/router.d.ts`,
и TypeScript начинает проверять адреса:

```ts
{ pathname: `/topic/[id]`, params: { id: string | number } }
```

Опечатка в адресе или забытый `id` становятся ошибкой компиляции. Но проверка действует только
на код, который мы пишем сами. Адрес, пришедший снаружи — из браузерной строки, QR-кода или
другого приложения, — для компилятора просто текст.

Поэтому параметр проверяется во время выполнения:

```ts
export function normalizeCountryId(value: unknown): string | undefined {
  const raw = Array.isArray(value) ? value[0] : value;
  if (typeof raw !== 'string') return undefined;

  const normalized = raw.trim().toUpperCase();
  return isValidCountryId(normalized) ? normalized : undefined;
}
```

Функция заодно приводит `/topic/jpn` к `JPN`, поэтому регистр в ссылке значения не имеет.

## Возврат

Назад работает обычным способом: системный жест, кнопка в заголовке или кнопка браузера.
Условия каталога при этом сохраняются.

Если истории нет — например, приложение открыли сразу по ссылке на карточку, — возвращаться
некуда. В этом случае карточка показывает кнопку «В каталог», которая делает `replace`:

```tsx
<TopicScreen id={id} showHomeLink={!router.canGoBack()} onHome={() => router.replace('/')} />
```

`replace` заменяет текущую запись истории, а не добавляет новую. Поэтому назад из каталога
пользователь не вернётся на карточку, из которой только что ушёл.

## Кто владеет состоянием

| Состояние | Где живёт | Что с ним при возврате |
| --- | --- | --- |
| запрос, фильтр, загруженные страницы, выбор, позиция прокрутки | `catalogMemory` + `CatalogProvider` над навигатором | сохраняется |
| данные карточки | `useTopic` внутри экрана карточки | загружаются заново |
| текущий адрес и история | Expo Router | сохраняется |

Пользовательский хук разделяет логику, а не данные: каждый вызов `useCatalog` создаёт свой
набор состояния. Два экрана, вызвавшие его независимо, не увидят состояние друг друга.
Чтобы данные стали общими, их нужно поднять выше — это и делает `CatalogProvider`
в `app/_layout.tsx`.

Этого оказалось мало. На вебе при первом переходе Expo Router пересоздаёт дерево маршрутов
вместе с провайдером, и состояние терялось. Поэтому значения дополнительно хранятся
в `src/hooks/catalogMemory.ts` — обычном объекте на уровне модуля. Модуль живёт, пока работает
приложение, поэтому пересоздание дерева его не задевает.

При перезапуске приложения память очищается: на диск ничего не пишется.

## Путь запроса из карточки

```
TopicCard → router.push({ pathname: '/topic/[id]', params: { id } })
          → app/topic/[id].tsx: normalizeCountryId(params.id)
          → TopicScreen → useTopic(id)
          → apiManager.countries.getById(id) + getPopulation(id)
          → transportService.requestJson()
          → https://api.worldbank.org/v2/country/JPN
```

Экран карточки не зависит от каталога: по прямой ссылке он работает, даже если список
ни разу не открывали. Проверено — запросов к `/country` при этом не уходит.

## Прямые ссылки

Схема приложения — `worlddex`, задана в `app.json`.

| Где | Ссылка |
| --- | --- |
| Браузер | `http://localhost:8081/topic/JPN` |
| Expo Go | `exp://ХОСТ:8081/--/topic/JPN` |
| Сборка с нативным кодом | `worlddex://topic/JPN` |

Проверялось в браузере после чистого старта: адрес `http://localhost:8081/topic/JPN` открывает
карточку Японии с населением, списка в фоне не загружает, и показывает кнопку «В каталог»,
потому что истории нет.

## Ошибки навигации

Четыре разные ситуации — четыре разных экрана.

| Что случилось | Пример | Что видит пользователь | Был ли запрос |
| --- | --- | --- | --- |
| Нет такого маршрута | `/unknown` | «Такой страницы нет» | нет |
| Параметр не похож на код страны | `/topic/12` | «Неверный формат кода страны» | нет |
| Код правильный, записи нет | `/topic/ZZZ` | «Такой записи нет в справочнике» | да |
| Сеть не ответила | любой адрес | «Нет связи с сервером» и «Повторить» | да, неудачный |

Первые две ситуации сеть не трогают вообще: приложение отвечает само. Разница между
`+not-found` и «записи нет» принципиальная. `+not-found` — про адрес: такого экрана в приложении
не существует, запрос не отправлялся. «Записи нет» — про данные: адрес верный, экран открылся,
запрос ушёл, но справочник не знает такого кода.
